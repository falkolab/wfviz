# Node guide: run history (unit run-history, P1)

Read with docs/guides/common.md; [stale-test], [stale-state], [flicker], [weak-test] and [guide-defect] apply (named where they bite). This file is ASCII only. Spec: the node task. Make any throwaway copy of the repo in a directory named after this node. Start wfviz only with --no-open and stop it only by `kill <pid>`.

## Rules that bind
- contract section 4, P1: in mode `real` the list holds "every run under the root, of any age and any project"; runs whose files changed within `--since` are "loaded at start (`loaded: true`: transcripts read, watched live)"; an older run is "listed from its journal, final file and script only (`loaded: false` ...)" and "loaded in full on its first `GET /api/runs/:id`"; "filter state lives in the URL hash, nothing is written to disk".
- contract section 1: "a source never invents values; a missing field stays missing"; "the source watches `root` with `fs.watch(root, { recursive: true })`"; stat polling is the fallback. Section 5: `sinceMs` = "only runs whose files changed within this window; Infinity = all". Header of claude-fs.mjs: a file position moves past a line only when its event was delivered, and nothing is delivered after stop().
- contract intro and AGENTS.md: wfviz is universal (test/integration/universal.test.mjs scans code lines of src/, web/, bin/); "Never invent data"; "The visualizer only observes: no endpoint writes, stops or starts anything"; "Write only the files your node owns"; Node >= 20, zero npm dependencies, no network. graph.md section 9: stop only the processes you started, by PID.
- AGENTS.md and the node file say src/model/ is not yours: use createStore and reduceRun as they are.

## Traps: source (src/source/claude-fs.mjs)
1. Same run state, two depths: the index and loadRun poll the same run object (offsets, hashes), so each line is emitted once in all. loadRun must not call readRunDir (a new state would repeat the three files' events). Test: index events plus loadRun events equal readRunDir's events by kind and prov.file:line, and the reduced Runs are equal (measured equal on 38 runs).
2. No invention: no new kind, no new data field, no `loaded` flag inside an event, no "now" for a missing ts. Loaded state lives in the source (`isLoaded(runId)`), never in the Run or the events. Index mode skips readdir of the run dir (pollRun with `index: true`) and every agent-*.meta.json, .jsonl and .prefix.json; the one window test per run (newestMtime) lists the run dir and stats its entries at first sight and opens nothing; the script named by the final file's scriptPath is part of the index (with its after-the-run warning).
3. loadRun(runId): unknown id rejects (never builds a path from the id; use Map lookups, `__proto__` must be unknown); a loaded run resolves at once; a call while a load runs returns the same promise, resolving only when it is done (else a second request answers a half-read Run); a failed or stop()-cut load is not marked loaded and can be tried again. Run it inside `exclusive` so it never overlaps tick or flushChanges on the same run state (two readers from one offset emit twice). isLoaded(runId) is false while a load of that id is under way (the `loading` map), so a run being read is not offered as loaded and the server sends no snapshot of a half-read Run; a call made while a load is half done gets the same promise and resolves only when it is done (test claude-fs-index, 'a call made while a load is half done').
4. One run id, several entries (measured, 3 of 38): loadRun loads every entry of the id; the id counts as loaded only when all do. The model takes `project` from the first event that has one (reduce.mjs:260) and the index reads the script first, so a split run lists under the script's project: do not patch it in the source; put it in your note.
5. Promotion: a listed-only run that is written to within sinceMs becomes loaded through the same path (the old intent of claude-fs-live.test.mjs). The window test (newestMtime) runs once per run at first sight (discoverSession), and once more when an indexed run delivers an event after its first index pass (pollTracked): only then, and only when the test says the files are within the window, is the run loaded (a write the window test does not see as recent, e.g. a touch -t set back, delivers its event and leaves the run listed only). It is not run on every full scan.
6. Watcher: still exactly one fs.watch call. A change under an unloaded run's agent files is dropped in onChange without a pass; journal, final and script changes of an unloaded run re-poll those three files only. Test with a spy on fs.watch (count 1) and a spy on fsp.open and fsp.readFile: no agent-* file of an unloaded run is opened or read (a stat for the window test is allowed). A timer or listener left after stop() fails the existing stop tests; add one for a pending loadRun (it rejects, nothing hangs). The drop is in onChange: classifyChange gives `file` (the name inside the run directory); a tracked run with loaded === false and a `file` that is not journal.jsonl is dropped; an unknown run, the run directory itself, the final file and the script pass.

## Traps: server and launcher
7. Loader: createServer gets an optional `loader` ({ isLoaded(id), load(id) }); the server knows no source. Without it (demo, replay, stand-ins) the list items are as today and the UI treats a missing `loaded` as loaded. Build it in main() after makeSource; add no key to the source options (bin.test.mjs:538).
8. GET /api/runs adds `loaded` to copies of the store summaries (never mutate them). /api/stream: the first snapshots and onStoreChange/queueSnapshot skip runs that are not loaded; a listed-only run has no snapshot until it is loaded. `event` frames stay as they are. GET /api/runs/:id: 404 first (visibleRun) without any load; then one in-flight load per run id in a Map (entry deleted when it settles, also on rejection); answer store.getRun after the await; a rejection is a 500 `{ error: <one-line reason> }`; do not write to a destroyed response and remove any per-request `close` listener when settled (pattern: handleReplay, server.mjs:390-397); HEAD and /events and /transcript start no load. No timer. When a load succeeds the server calls onStoreChange(id), so the clients of the stream get the first snapshot of the run that has just become loaded (none was sent while it was listed only).
9. Launcher: --since keeps its meaning (which runs are loaded at start); edit only HELP_NOTE (printed after usage() on --help, after a blank line) and the header comment of bin; src/server/args.mjs is not owned (see Own), so the stale `--since` line stays in usage() and HELP_NOTE is the text that says how to read it: it must keep saying that every run is listed, that --since does not hide older runs and that it chooses what is loaded at start. Never edit or filter the usage() text from bin/wfviz.mjs to hide that line (a string replace on another module's output breaks silently when it changes, and usage() is printed on a usage error without the note).

## Traps: web (web/app.js, lib.js, index.html, style.css)
10. Hash state, `#range=all&project=..&status=..&from=YYYY-MM-DD&to=..&q=..` (defaults omitted; empty hash = last 24 h, nothing else set). Parse and format are pure functions in lib.js, tested without a browser: unknown range, from/to that are not a real calendar date, values over 200 characters, repeated keys (take the first), malformed percent-encoding (use URLSearchParams, never decodeURIComponent) fall back to the default; unknown keys are dropped. The project and status values are checked against the list only after it arrives (an absent value resets to all and rewrites the hash). Write with history.replaceState inside try/catch (it throws in a sandboxed frame), never `location.hash =` (history entries, hashchange); one hashchange listener on window, added once at load. No localStorage for any of this. Parse and format are lib.js parsePickerHash and formatPickerHash (tests: web-run-history.test.mjs); the filter and the options are runPassesFilter, pickerFilterOptions and sanitizePickerFilter. A hash value that is a project or status the list does not have is reset after the list arrives and the hash rewritten (web-u4 'run history: invalid hash values ...').
11. Rules the spec leaves open (stated so the guide agrees with itself): the 24 h window applies when neither from nor to is set and range is not all (an explicit date range replaces it); a run whose startedAt is unknown is outside 24 h, from and to and shows only under all with no date set; the text filter is the existing search (name and id), not a second box; options of the project and status filters are built from the list's own values (a status text we do not know stays filterable; no hard-coded method statuses, universal.test.mjs); the project is shown exactly as the dir name on disk (no dashes turned into slashes: the encoding is lossy). Open the first page on a loaded run only (running one, else the first loaded); with none loaded show an empty-state line, never an unasked load (app.js:195-198 picks state.runs[0] today). Shipped form of the project and status controls: `<input type="text" list=...>` with a `<datalist>` each (index.html holds no `<select`, a pin in web-u4), committed on `change`: a typed value that is not one of the list's values becomes "all" again and the field says so; the datalist options are a keyed list (written only when the set of values changes). A control takes a value only when the filter it shows has changed since it was last written (state.picker.ctl), so a snapshot never overwrites what is being typed. The "all" switch is `#rp-all` (a checkbox in `#rp-filters`), the dates `#rp-from` and `#rp-to` (type=date, local days, both ends included), the count `#rp-count`, the note beside the button `#rp-note`.
12. Rows: a row of a listed-only run says "not loaded - opens on click" in its meta span; while its GET is out the same span says "loading..."; the other rows keep their DOM nodes (assert element identity and the fake DOM's `writes` counters). summaryOfRun must set loaded: true (a snapshot exists only for a loaded run) and a successful GET flips the row. fetchJson now returns `reason` (the `error` text of a failed answer's JSON body) next to its `error` (`HTTP 500`); selectRun shows `could not load <id>: <reason>` in `#rp-note` and in the empty view. renderEmpty and setHtml take HTML: the reason, the project, the filter text and every hash value go through esc() or textContent/value/setAttribute, never into a class name. The control options are written only when their set of values changes. The existing triggers are the page start and the stream (app.js:1709): add no poll. A row also shows the project exactly as the list gives it (span `rp-proj`) and a listed-only row has the class `unloaded`. A run chosen again after a failed load is loaded again (chooseRun).
13. Geometry [guide-defect]: the filter bar sits inside `#rp-panel` (fixed, 14 px gutters, list scrolls) and wraps at 375, 800 and 1228 px with no horizontal overflow of the panel. Measure with evidence/tmp/cdp.mjs (headless Chrome, not the browser pane): panel scrollWidth <= clientWidth, list scrollable. The ui-check covers only what this cannot. Measured on the shipped code with evidence/tmp/run-history-geometry.mjs (own wfviz on a temp root, headless Chrome over CDP, #range=all, picker open; output evidence/tmp/run-history-geometry.out.txt; the same script on a `git archive HEAD` copy: run-history-geometry-baseline.out.txt): the panel's scrollWidth equals its clientWidth at 375 (345/345), 800 (770/770) and 1228 px (778/778); the filter bar wraps inside the panel (75 px high at 375, 25 px at 800 and 1228) and no control lies outside the panel; `#rp-list` has overflow-y auto (this root has 3 rows, so no scrolling was needed and none was measured). At 375 px the PAGE scrolls sideways (document scrollWidth 563 against 375) from the `#run-status` stats; HEAD does the same (563/375), so it is not this node's.

## How to check each item by hand
- Source: build a temp root with two project dirs (cp -R fixtures/claude-projects, rename the slug for the copy), set one run's files back with `touch -t 202511010000` on every file; run the source with watch false, pollMs Infinity, sinceMs 24 h and count events by kind per run: old run = launched, started, result, failed, script, final only; await loadRun(id) and count again; a second call adds nothing.
- Server: `node bin/wfviz.mjs --no-open --port 0 --idle 0 --root <temp root> & echo $!`; `curl -s 127.0.0.1:<port>/api/runs` shows loaded true and false; `curl -s .../api/runs/<old id>` returns agents and the list then says true; `curl -sN .../api/stream | head -c 2000` has `run` frames of loaded runs only; a missing id is 404 and loads nothing; `kill <pid>`.
- Web: parse and format on the invalid values of trap 10 (test/server/web-run-history.test.mjs); the fake-browser tests for rows, keys and escaping (web-u4, section 'run history': a project named `<img src=x onerror=alert(1)>`); evidence/tmp/run-history-geometry.mjs for trap 13.
- [weak-test] before issuing a test, delete the guard it pins in a throwaway copy and see it fail: skip-unloaded in the stream, one-load-per-run, drop-agent-file-change in onChange, the one-promise rule of trap 3.

Tests of this node (shipped): test/source/claude-fs-index.test.mjs (8: the index over two project dirs with old runs and no agent file opened, loadRun once and equal to readRunDir by kind and prov.file:line and by the reduced Run, unknown ids reject, a run id in two session dirs, promotion, one fs.watch and the dropped agent-file change (no stat, no open), a call during a half-done load, stop() during a half-done load), test/server/run-history.test.mjs (9: list with `loaded`, lazy GET, one load per run id, 500 with the reason, 404 and HEAD start no load, a client that leaves, stream skips listed-only runs and sends the snapshot after the load), test/server/web-run-history.test.mjs (7, pure), web-u4 section 'run history' (9, fake browser) and test/integration/run-history.test.mjs (3, the real launcher: list, lazy GET equal to a --since Infinity server's answer, stream, --help: the note follows the --since line and says that every run is listed, that --since does not hide older runs and what it chooses, and that an older run is loaded when opened).
