# Node guide: matrix cells (unit matrix-cells)

Read with docs/guides/common.md: [stale-state] and [flicker] bind any markup you touch (same DOM node kept, nothing removed and re-added with identical content); [guide-defect] is why "How to check" has a geometry gate you run yourself. The spec (items 1-4) is in the node task; this file says what binds, what you may break, where it is easy to go wrong, and how to check. Tests are named, not numbered by line.

## Rules that bind
- docs/contract.md, intro: "wfviz is universal"; no role, phase, label, node code, file name or result shape of our method "may be required or hard-coded" in src/, web/, bin/. test/integration/universal.test.mjs scans every code line of web/; a trailing // comment counts.
- contract §2: "Every value the UI shows is a **Fact**"; "Label pattern (inferred, never required)": everything after the last `#` is the tag, "any text" (a tag may be long, hyphenated, or hold spaces); "Fallback matrix": cells "captioned with the label as is"; the role x unit matrix "is shown as soon as one agent label parses" (one row with one cell must lay out too).
- AGENTS.md, Hard rules: "Never invent data."; "Roles, phases and labels come from run data, never hard-coded."; "The visualizer only observes"; "Write only the files your node owns."; "Never run `git stash`, `git reset` or destructive commands. Workflow agents do not commit"; "ES modules, Node >= 20, zero npm dependencies."
- AGENTS.md, "Images and video": no screenshots in the session; this task also forbids the browser pane (mcp__Claude_Browser__*). Measure with numbers, report numbers as text.
- graph.md §9: "A node's gate can block on a test outside its owned paths that asserts the old contract; the fixer cannot touch it."; "A node whose spec changes behaviour that another node's tests assert must own those test files"; "Workflow agents must stop only the processes they started, by PID"; test/server/index.js loads every *.test.mjs, so the new file needs no list. Only high and medium findings send work back.

## Files you own and tests the spec touches
- Own: web/style.css, web/app.js, web/lib.js, test/server/web-u5.test.mjs (new; `test` from ./helpers.mjs; do not import web-u3 or web-u4, their tests would run twice). The three defects are layout: expect to edit style.css and the new test only; touch app.js or lib.js only if a rule cannot be written without a markup change, and say so in the note. Not yours: web/index.html, src/, bin/, every other test.
- Expected to fail: none. A shared test below that you break stays broken for the fixer (not its file): keep it green, or name it in the note.
- web-u3 "page: a unit name or a role is wrapped, never cut..." reads the FIRST `.mhead {`, `.mrow-label {` and `.mrow-label .u {` rule that starts a line: none has `text-overflow: ellipsis` or `white-space: nowrap`; `.mhead` and `.mrow-label .u` keep `overflow-wrap: anywhere`. Add declarations inside those rules or in rules after them; keep `anywhere` on `.u` (it acts only on a word that fits no line); no `white-space: nowrap` on `.u` or on the tags (shipped: a tag is kept whole by `flex: 0 0 auto`, see Traps).
- web-u4 "keyboard focus: the toggle of a unit history keeps its element..." fixes the label's DOM: the toggle, `.u-name` and the `.tag-i` tags are children of one group, that group is the child of `.mrow-label`, and an identical snapshot writes nothing to any of them. The tags cannot move into a new wrapper: do the line break in CSS.
- web-u4 "wide matrix..." counts 15 `.cell` elements as direct children of #matrix-grid and the string `repeat(15, minmax(44px, 1fr))`: no row wrapper. The flicker tests (COUNTER_LIKE) let an event write only an agent's own elements and `.mrow-label`, `.mhead`, `.matrix` and the like.
- web-u3 "new text from data reaches the page through esc()" needs the literals `esc(x.tag)`, `esc(x.state)`, `esc(r)`, `esc(g)`, `esc(u)` in app.js. web-u4 "page code..." lists every `setHtml(` call (add none), counts one `setInterval(` and two `setTimeout(`, and needs `grid: listOf($('#matrix-grid'), { create: makeNode, update: updateNode })`.
- web-u4 universal scans: no class or custom property in web/ with the whole word impl, rev, judge, fix, test, accept, implement, review, reviewer or fixer (split on - and _), and no `U5`, `Node U5`, `(item 3)` or `web-u5` in a comment of web/. Name classes by function (`.u-tags`, `.ca-state`), not after the tags of the defect report.

## Traps
- No change in what is shown. No new text, number, icon, title or ordering; the `×n` badge, "no tag", the state words and the `data-n`, `data-tags`, `aria-label` attributes stay. An empty cell (`.cell.empty`) is a cell of its row and stretches too. A row with no tags shows no tag line and must not grow: a zero-height `::after` line adds its row gap (measured 70.6 against 68.6 px with `gap: 2px`); use `row-gap: 0` and a margin on the tags.
- Item 1 is CSS only: cells and labels are siblings in one grid, so `align-self: stretch` on `.cell` and `.mrow-label` (or `align-items: stretch` on `.matrix` with `.mhead { align-self: center }`) does it. No measuring in JS (offsetHeight, ResizeObserver, timer, listener, inline height). Header cells keep their centring; `.hist` (`grid-column: 1 / -1`) is a grid item too; cell content is already centred (flex column, `justify-content: center`); do not centre the label's content, the spec does not ask.
- `.cell` is shared: fallback rows use `.cell.fb-cell` inside `.fallback`, a flex wrap that already stretches per line. Do not change the base `.cell` gap, padding or min-height for the matrix; two `.cell {` rules exist; a later `align-self` on `.cell.fb-cell` or `.cell.empty` undoes item 1 in one place. `.tag` is also in the picker, report, history rows and finding cards: change only `.cell .ca .tag`.
- Item 2, measured (headless Chrome, old rules): state tags are 12 px tall and the next starts 0.7 px ABOVE the previous one's bottom, so they overlap. The spec's "padding 0" is really `0 3px`; `.tag` elsewhere is `0 4px`. Vertical padding on an inline tag grows its box, not its line (padding 1px 4px, gap 3px, line-height 1.3 still gave 0.7 px); `display: inline-block` with its own line-height and gap 2px gave 2.0 px. Pin what you measured and name the numbers.
- The space between "#tag" and the state tag is the literal space in `#${esc(x.tag)} <span class="tag ...">`: add none. A flex or grid `.ca` drops it (measured: text 27.1 px against 32.5, tag touching); then use gap or margin, never `&nbsp;`. The "no tag" line is a `<small>` at 11 px inside 9 px lines: it gets the same spacing.
- Item 3, width. The label is the first track of `.matrix`, `minmax(120px, 1.4fr)` set in renderMatrix (not the page's left aside). With a matrix of nine roles at 1228 px it sits at that 120 px minimum: 102 px of content, 21 px of it the toggle and its margin. "web-polish" is 78.3 px at 13 px mono and fits beside the toggle only with no flex column gap (name box 81 px; a 4 px gap gave 77 and the name broke at the hyphen again). Decide how to make room (no gap, smaller toggle margin, toggle alone on its line when the name does not fit, wider track), measure at 120 px, name the choice.
- Item 3, tags. Shipped (after the judge's findings): `.u` flex-wrap with `row-gap: 0`; `.u-name { flex: 0 1 auto; min-width: 0 }` (a basis of 0 breaks the name at its hyphen when it fits the column); `.u::after { content: ""; flex: 0 0 100%; order: 1; height: 0 }`; `.tag-i { order: 2; flex: 0 0 auto; max-width: 100%; margin: 2px 4px 0 0 }`, no `nowrap`. A tag that fits the column stays whole (no shrink). A tag wider than the column is held to it by `max-width` and breaks inside as the last resort, shown in full: with `nowrap` it ran under the next column's opaque cell and its tail could not be read (judge-approved finding, 9 roles, 120 px track, an 18+ character tag).
- If you change a markup string: keep the keys (`keyOf('cell', u, m.roles[i])`, `keyOf('row', u)`, `keyOf('tag', g)`), the same `morphHtml` path, no new innerHTML write, no timer, no listener. Every data string, attributes included, through esc(); `data-unit` stays a raw attribute (esc would show `&amp;`).
- Coupling: `#prep`, `#rule-full`, `web-polish` of the defect report live in your test data only, never in web/ (code, comment or class). Test Runs may use any labels; the page assumes none.
- The test (item 4): pure checks over the css text with comments stripped and over app.js. Write the checks as one function over css text; call it on web/style.css (no failures) and on a string with the old rules (`.matrix` centring with no stretch on `.cell`/`.mrow-label`, `gap: 1px; line-height: 1.15`, a name with `flex-basis: 0`, a tag with `white-space: nowrap` or without `max-width: 100%`), where it must report each defect; never restore the old file with git. Resolve the cascade over every rule whose selector list holds the selector (two `.cell {`, comma lists), not the first match. Keying: from `matrixRows` of units and roles that hold `,` `|` `:`, every `keyOf('cell', row.unit, cell.role)` differs, and app.js still has that call. No conditional skip: the gate wants skipped 0.

## How to check each item by hand
No server is needed. In your scratch directory (not the repo) build a static page: `<link rel="stylesheet" href="file:///.../web/style.css">`, a 560 px box with a `.matrix` (`grid-template-columns: minmax(120px, 1.4fr) repeat(4, minmax(44px, 1fr))`), heads, one row with the label markup of rowLabelGroup (toggle, name, nine tags: `#a`, `#rule-b`, ...) and cells (one agent, four agents, empty), a second row with no tags, and a script that writes getBoundingClientRect() as JSON into a `<pre>`. Run `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --virtual-time-budget=2000 --window-size=800,900 --dump-dom file://...`, again at 1228. If you start wfviz, pass `--no-open` and stop it by its PID. Old rules measured: label 159.5 px, cells 46 / 72.4 / 46 / 46, label tags up to 31.2 px tall (two lines).
1. Every `.cell` of a row and its `.mrow-label` have equal height (+-0.5 px), empty and one-agent cells included; `.mhead` rects as before (19.4 px); the fallback rows unchanged. The sketch above gave 155.5 px for all.
2. Between the state tags of a cell next.top - prev.bottom >= 2 px (sketch: 2.7); text and tag are one space apart; a "no tag" line spaced alike; a one-agent cell has no `.cell-agents` and is unchanged.
3. The name is one line (about 18 px) at the 120 px track; a name with no hyphen that fits no line breaks, nothing else does; tags start below the name, each one line (15.4 px) when it fits the column, wrapping between tags; a tag wider than the column wraps inside the label and its right edge stays left of the next column (elementFromPoint at its end returns the tag, not a `.cell`); the unit with no tags keeps its old height (68.6 px); `.col` gets no new sideways scrollbar.
4. The check function is empty on web/style.css and reports 3 defects on the old rules; an empty cell (no agent of that unit and role) has its key too and counts as a cell.
Unchecked (ripple, colours, hover panel at the window edge): list for the ui-check. Before finishing run `node --test test/` once: exit 0, fail 0, skipped 0, todo 0, pass > 0 (984 passed before; yours add). Expected failing tests: none.
