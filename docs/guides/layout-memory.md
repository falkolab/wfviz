## Traps
1. Persistence across launches (not yours to fix, report it). The default port is 0 (any free port), and localStorage belongs to one origin, port included. Measured 2026-11-15: two starts gave 127.0.0.1:58161 and :58400, so a second start sees empty storage. Everything here survives a reload and a restart with the same `--port N`, never a plain restart. Fake-storage tests cannot show it. Say so in your note; the fix (a stable default port with a free-port fallback) is a server node for the orchestrator. Do not work around it with an endpoint or a cookie.
2. Width rule. `viewport().width` (grid inner width, window minus 28 px of padding) is the width clampLayout already takes; use it, never window.innerWidth. Add a pure `defaultColumns(width)` in lib.js: 480/600 when 1080 fits, else both shrink in 4:5 so the centre is at least half. Decide whether the two 8 px handles count against the centre and name it in the note; test exact numbers from your formula, not the spec's "about". Handles counted: the rule binds below width 2192 (1440 gives 312/391, 1920 gives 419/524, 2560 gives 480/600); not counted: below 2160 (320/400, 426/533, 480/600). So 1440 and 1920 both bind and only 2560 does not: a test that expects 480/600 at 1920 is wrong. Test the threshold at -1, 0, +1. Ratio test: `Math.abs(5*left - 4*right) <= 5` (floor). Width 0, NaN, undefined: no throw and the existing minimums (web-u3 "a window with no size gives the minimums").
3. Stored wins. A stored side keeps going through the existing clamp; only a missing side takes the default (put it in clampLayout's `pick`, no second code path). A drag starts from the shown values (so the other column does not jump), but it never copies all three shown sizes into state.layout, because that freezes a side that was only shown at its default (a log drag at a grid of 1440 would keep 312/391 in a grid of 2560, and nothing would be stored for them). After a moved drag state.layout holds only: the dragged size; a size that was already wanted, at the width on show; a size the drag shows off its default (a side squeezed by a stored wide one keeps its shown width, so the drag stays under the pointer). That is the pure `wantedAfterDrag(before, sized, kind, viewport)` in lib.js, built at every move from a copy of state.layout taken at the press, never from an earlier move. A side that was only shown at its default stays unset and keeps following the window, in the session and after a reload. Only the dragged key is stored. Tests: a log drag, then a window of 2560, shows 480/600 and stores only the log; the same for the left and the right handle; an already wanted side stays; a squeezed side keeps its width during the drag; a drag that leaves the default and returns leaves the other side unset. Never `Object.assign(wanted, shown)` (common.md, [stale-state]).
4. CSS first paint. app.js is a module script, so the first paint uses `var(--left-w, 240px)` (style.css line 129). Set the fallbacks to the same result as the JS default (for example min(480px, 22%) and min(600px, 27%)) and leave the @media (max-width: 1100px) rule and `--log-h, 190px` alone. Measure it, do not claim it.
5. Resize. The existing `window.addEventListener('resize', ...)` already calls applyLayout (CSS variables only, setStyleProp skips equal values): the default is recomputed there with no render. Add no second resize listener. If you add the one rAF, use a pending flag like edgesQueued. The fakes set `requestAnimationFrame` to `() => 0` (never runs the callback): a resize test must install its own that runs it, and must change width through page.windowListeners.resize.
6. Storage keys and values. Use three new keys, never one key per run: `lastRun` (id text), `filters` (text), `runState` (JSON). Export a fixed `STORED_KEYS` list from lib.js (the three layout keys, logCollapsed, view, replay.speed, hint.closed, the new three); a test greps app.js for every localGet/localSet key and requires it in the list, so a new key cannot be forgotten. No key name may contain "hint" except hint.closed (web-hint's fake counts every key matching /hint/). `wfviz.logCollapsed` is written at every boot already; so right after a reset the keys are gone, and after the reload that one reappears: check before the reload.
7. Last run. The address never carries a run (the hash holds six filter keys, parsePickerHash drops others), so "address has no run" is `!state.runId`; do not add a run key to the hash. Look the id up with `state.runs.some(r => r.id === id)`; a gone id changes nothing and shows nothing. Write `lastRun` in selectRun only when the id differs from the stored one (a reconnect calls selectRun again) and not while replayOnShow(). A listed-only run (`loaded: false`) is opened too, as the spec says. The remembered run beats the running one; name that in the note.
8. Filters. Store formatPickerHash(state.filter) text and read it back with parsePickerHash only: no JSON, no second parser (round trip pinned in web-run-history). "No hash" means nothing after `#`; any hash wins whole, no per-key merge with the stored text. Apply the stored text before the first renderRunPicker and write it with writeHash(), placed after the `const state = {...}` statement (inside the literal it throws a temporal-dead-zone error). Write storage in setFilter and in the sanitize step; a hash read at load or on hashchange never overwrites it. Clearing every filter must store the empty text, or the next bare load brings the old filter back. A stored project or status the list lacks is reset by the existing sanitize step.
9. Per-run memory. Entries are `[runId, { expanded: [...], tests: true|false, weak: true|false }]` in an array (or Map), never a plain object: a run id `__proto__` is a key like any other. Pure functions in lib.js: parse (try/catch, array check, id a string up to 200 chars, expanded an array of strings up to 200 chars each and at most 100, booleans only when `=== true`, extra fields dropped, cut to the newest 50 on read), and update (the changed run moves to the end, an entry equal to the defaults is deleted, the oldest beyond 50 is dropped). "Most recent" is last changed by the user, never run start time (unknown for some runs). Merely selecting a run writes nothing; otherwise 50 looked-at runs push out the ones that hold state. Write only from the existing handlers (the `[data-unit]` and `[data-tests-toggle]` branches of the one document click, the `#weak-toggle` onchange property).
10. Restore. In selectRun, when `!keepDrawer`, state.expanded, testsExpanded and state.weak come from memory instead of empty, and `$('#weak-toggle').checked` is set from state.weak (a checkbox keeps its own state across runs). A reconnect (keepDrawer) leaves all three alone. beginReplayView (about line 1878) starts a replay empty: the replay view neither reads nor writes memory (recommended; decide, test, name it).
11. Reset. A static `<button id="reset-layout" type="button">Reset layout</button>` in index.html beside #hint-open (no innerHTML, no new document-level listener: `$('#reset-layout').addEventListener('click', ...)`). `confirm` may be missing, throw or return false: then nothing is removed and nothing reloads. Remove each of STORED_KEYS through localRemove (foreign keys and `wfviz` keys not in the list stay; the test uses a foreign key and checks exactly). Call reload only if `typeof location.reload === 'function'`, in try/catch. The hash survives a reload, so the filters in the address would come back: recommended, reset also sets state.filter to the default and calls writeHash() before the reload; name your choice. The confirm text is a fixed string.
12. Timers and listeners: none new beyond item 5. Escaping: no data string reaches innerHTML, a selector or confirm; Set.has and string compares only.
13. Coupling: nothing of our method on any code line of web/ (no 'implement', 'judge', 'fix', node codes, file names); test Runs may use our labels.
14. The header is flex-wrap: the new button must not push the page into a horizontal scroll at 375, 800 or 1228 px.
