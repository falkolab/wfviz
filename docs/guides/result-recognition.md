# Node guide: result recognition (unit result-recognition)

Read with docs/guides/common.md: [stale-state] and [flicker] bind every list and view you touch (same DOM node kept, nothing removed and re-added with identical content); [guide-defect] is why each missing-value case has one sentence here and the closing line names the failing tests. The spec (items 1-6) is in the node task; this file says what binds, what you may break, where it is easy to go wrong, how to check. Tests are named, not numbered by line. The file is ASCII only; the spec-reporter character in recognize.mjs and its tests is U+2139 (raw in those files).

## Traps
- Run.result is the final file's `result` as is: a Fact, prov final, from = finalFrom('result') (text `<final file>#result`). Unknown cases, each with its own reason: no final file (still running: "written only at the end", as `error` and `logs` say; else no final file), `"result": null` (the failed run), no `result` key (test with Object.hasOwn). Any other value, array included, passes through; no handling for a string or number result (none seen). Never fill it from the last agent, from `resultPreview`, or with `{}`; never cut it. Set it before `run.recognized = recognize(run)`. Recommended: add `result` to the fields collectUnknowns lists beside `logs` (a prototype broke no extra test).
- recognize(run) must not throw and must add nothing for a Run with no `result` key (the recognize tests pass only {order, agents}), `result.prov === 'unknown'` or a null value: "a run without these fields must look exactly as today". Order: agent items in run.order, then run-scope items. Do not mutate `run.result.value`.
- Every item gets `scope`; run-scope: `agentId: null`, `from` = Run.result.from ?? null. A consumer treats only the string 'run' as run scope; a missing or other scope counts as agent (old web tests feed none). One helper in lib.js decides it.
- Shape rule, decisions the contract leaves open (generic: never the names `missed`, `low`, `confirmed`, `category` in src/ or web/): (1) `<keys>` is per item: the keys present among line, severity, description, input, in that order, joined by +, e.g. `shape:file+line+description`. (2) "has" is `key in item` as the by-name rule: `{file: null, line: 0}` counts; no type or truthiness check. (3) An array under findings, issues or problems (any case) is by name only and never also by shape, so no item counts twice. (4) A top-level array has no key and is not matched; nor is an array directly inside an array. (5) One string, null or non-matching item makes the whole array not findings; empty is not. (6) An item copies file, line, title, description, severity, input where present, nothing else. (7) `path` as today (`$.low[0]`).
- Do not dedupe across scopes: a run result often repeats what an agent returned; both stay, each in its place. Never add run-scope counts to agent counts, never drop one as a duplicate.
- reportCard: keep status, durationMs, error, agents, `findings` (a number) and `verdicts` {total, byValue}, now agent scope. `tests` becomes {reports: agent-scope tests items, total: the single run-scope item's passed, failed, skipped, todo, method, from, prov 'inferred' | null, reason}; add run-scope counts for findings, verdicts, tests (null when all 0). Reason: none (when Run.result is unknown, copy its reason), or says how many run-scope items. No sum of agent reports, no "last of" anywhere (assert it is gone from app.js). `todo` only when the item has it; a missing count stays "?" as `n()` does. A Run with no `result` or `recognized`, and reportCard(null), do not throw and count as no run-scope item.
- A run-scope item has no agent. `agentLabel(run, null)` returns null and testRows would label it "null": run-scope rows say "run result", get no `data-agent` (specOf drops null), a key that cannot equal an agent's, their own "k of n". `findingCounts` skips them. renderRight sorts by the agent's endedAt and cuts at 60: an invented 0 would sort a run item last and cut it; keep run-scope cards in their own keyed group before the agent cards, only when there are some (a run without them keeps exactly today's children). Counters stay agent-only plus "+ N in the run result" when N > 0 (recommended; name your choice). The card line "in the run result: N findings, M verdicts, K tests" shows only when any is > 0, as its own keyed spec.
- Click: run-scope elements carry `data-result` (not data-agent, not any data-run name) and one branch in the existing document click handler, before the `[data-agent]` branch, returns. It opens #drawer with the Run.result JSON (`JSON.stringify(value, null, 2)`, a string as is) in a keyed `pre` of lists.drawer, with its prov and from. Opening sets state.drawerAgent = null, clears state.trTimer, bumps state.trToken (an agent transcript in flight must not draw into it) and clears lists.drawer when it comes from the other view, as openDrawer does for another agent. closeDrawer (the x button, Escape, selectRun) must close it; render() refreshes it through the patch (same `pre` node, same scrollTop over equal snapshots). No new timer, listener, setHtml or innerHTML write.
- Escaping: every string from run data (file, line, description, severity, input, title, path, from, method, verdict, reason, the result text) goes through esc(); a result holding `<img onerror=x>` or a key with a quote must show as text. A new lib.js export must be a function. Labels stay generic ("run result"); no comment in web/ names an item number or a node.
