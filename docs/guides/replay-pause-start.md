## Traps
- Item 1, lib.js createReplayQueue. Keep `keptAtPause = items.length > 0` set in pause() after the `pausedAt !== null` early return (a second pause call must not reset it) and per pause, not once per queue. resume(): `if (keptAtPause) offset += max(0, now - pausedAt); else if (items.length > 0) offset += max(0, now - due(items[0]))`, before `pausedAt = null` and the drain; due is arrival + the offset before this resume. Measured against the spec: pause 100, resume 10100, a frame at 10100: applied at 10100, offset 0, no timer. Pause 0, frame at 9900, resume 10000: applied at 10000, offset 100. Arrivals 0, 100, 400, pause 50, resume 1050: 0, 1050, 1350. A frame waiting due 1350, pause 1200 for 500: applied at 1850. Beyond the spec (measured): offset 490 from an earlier pause, a pause with nothing kept, a frame arriving in it due at 2590, resume at 2200: offset grows by 0 and the frame plays at its own due time 2590 (a timer is armed); a second pause() call after a frame arrived must not flip the flag (pause 10 with nothing kept, a frame at 500, pause again at 520, resume at 600: applied at 600, offset 100; a re-read flag gives 1090).
- Decision, the snapshot rule: "first kept frame" is `items[0]` at Resume, not the first frame that arrived. Pause at 0, snapshots at 100 and 300 (the older is dropped), resume at 1000: the newer plays at 1000, offset 700 (measured); the other reading gives 1200 and contradicts "shown at Resume". Pin it with a test and say so in the note.
- The old node's trap about Pause during 'connecting' (a replay delayed by the paused time although the view was never behind) is the case this node fixes: Pause at 100, Resume at 10100, hello and the first event at 10100: applied at 10100, no timer. Test it at page level too. The lib test "a resume with nothing kept still counts the time paused" and the page test of the same name assert the old rule: invert them (nothing kept, 500 ms pause, a frame at 700 applied at once at 700, no timer).
- Offset never shrinks (`max(0, ...)`), one timer at most, none while playing with nothing kept, clear() and the pass-stops-at-once rules unchanged. Update the comment above createReplayQueue, the `offset` getter comment (it is no longer "the total time paused") and the two app.js comments that state the old rule ("the view runs behind the stream by the time paused", "each at its arrival time plus the time paused"). The comments must not name how this project is developed. Mutation checks ([weak-test]): resume always adds the paused time; drop the `max(0`; use the last kept frame; forget the flag at the second pause(): each must turn a new test red.
- Item 2, app.js selectRun.
