## Traps
- Item 1, invent. No address names a run on this page: parsePickerHash keeps range, project, status, from, to and q, and state.runId is set only by selectRun. "An address that names a run still wins" is therefore the existing `!state.runId` guard, kept as it is; add no hash key and no storage key.
- Item 1, the function (suggest chooseStartRun(items, rememberedId), no storage access; app.js passes parseLastRun(localGet('lastRun'))). One sentence per missing value, repeated in its test: an item without `loaded` counts as loaded (as isLoadedItem does today); `loaded: false` is never "running", whatever its listed status says; a missing or unknown `status` is not running; a null or non-object entry, or one without a string id, is skipped; `items` that is not an array gives null; a remembered id that is not a string or not in the list is ignored; a remembered run that is only listed still opens; several running runs give the first in list order, not the remembered one (state.runs puts stream-only runs first); nothing loaded and nothing remembered gives null and app.js keeps renderEmpty(NONE_LOADED). It reads only id, status and loaded: no label, role or name. The picker's 24 h filter does not hide a run from this choice (it reads state.runs, as today).
- Item 2, order (measured). Clamping each side to half the width before shrinking turns stored 700/800 at 1440 into 700/720 and shows 347/356 (ratio .975, not .875). Shrink the finite raw wishes together first (floor of wish * bound / sum, so the sum stays under the bound), then apply the minimum and maximum. Limit each wish first to 2^40 (WISH_MAX, far above any width a person stores): two wishes near Number.MAX_VALUE add up to Infinity, Infinity / Infinity is NaN, between(NaN, ...) stays NaN and the page would write `--left-w: NaNpx`; `parseStoredSize('1e308')` accepts such a text, so a hand-edited store gets there. Below the limit nothing changes (the finite path is the same numbers). A minimum raised after the shrink breaks the bound (9999 and 160 at 1400 gave 556/160, centre 668 of 700): the other side then takes bound minus 160, 524/160.
- Item 2, bound. Use the integer `Math.floor(width / 2) - 2 * HANDLE_WIDTH` (a fractional bound plus the final Math.round can put the sum one over). Leave defaultColumns alone (other tests pin its exact numbers; below 2192 its two defaults already add up to the bound). Keep the CENTER_MIN rule as well; it never binds above width 480 and COLUMN_MIN wins below 672.
- Item 2, numbers (measured, stored 700/800, no prefer): width 1440 gives 328/375 (centre 721), width 1280 gives 291/332 (centre 641), each within a pixel of 7:8. Drag at 1440 from the shown 312/391: left +500 gives 313 beside 391, right 500 to the left gives 392 beside 312, centre 720 = half. Width 600 gives 160/160. A sweep of widths 1101..2600 x prefer null/left/right x wishes {unset, 50, 160, 200, 300, 500, 700, 800, 1500, 9999} (450,000 cases) kept the centre >= width / 2 in every case; test a sweep like it, because the three spec cases miss the minimum trap. Re-measured: `{ left: 1e308, right: 1e308 }` at 1440 gives 352/352 (before the limit NaN/NaN), one 1e308 beside 300 gives what 9999 beside 300 gives, a negative 1e308 is the minimum; sweep huge wishes (1e308, 9e307, Number.MAX_VALUE, 1e300, 2^60, -1e308) beside every other wish, both sides, prefer null/left/right, widths 672..1e6, and assert whole numbers, both columns >= 160 and the centre >= half.
- Item 2, decide and name. A missing side (default) and a stored one go through the same shrink (stored right 450 beside the default left 312 shows 288/415): one rule, no second path. Because the defaults fill the bound, at 1440 and 1920 a column cannot be widened until the other is narrowed; that is the spec ("the other column unchanged when it fits"), so tests that widen must narrow first.

- Item 4, the history and the last track (re-measured). `.hist` is a child of the matrix grid with `grid-column: 1 / -1`: spanning only the capped tracks it is 444 px wide for one role (280 + 160 + gap), and its label column (the 1fr track of `.hist-row`) is 63 px, so the agent label is cut to a few characters; the last track makes it as wide as the grid (static page, one role, window 1468: hist 1445, label 1064; real page, centre 721: hist 698 = grid, centre 961: 938).
