## Traps
1. Inventing a value (a). A demo Run shows no cost cell and no cost row at all: not "$0.00", not "cost unknown: not found", not an empty cell. Its four counters and the engines note stay. state.prices stays `idle`; the page makes no `/api/prices` request on its account. Demo means exactly `run.source === "demo"`: not the id prefix `demo-`, not the hello mode, not a missing source (a Run with no `source` or any other value keeps today's cost line; `agentNeedsPrices(agent)` with one argument counts as not demo). A demo Run does carry usage (made up): that is why the gate is needed.
2. Server order (a). The mode check comes before the offline check and before any fetch, for GET and HEAD, with or without --offline (demo plus --offline is 404, not 503). Methods other than GET and HEAD get 405 at line 1108 before the route, as everywhere. `/api/prices/x` is the ordinary 404. Do not add a flag or a timer.
3. Inventing a value (b). N = sum over the four counters of max(0, usage[k] - sum of byModel[k]); an integer written with String(), never toLocaleString (the counters elsewhere use fmtNum and a comma; N does not, so a machine's locale cannot change the text). A counter where the split exceeds the usage counts 0, it never offsets another counter. N = 0 leaves the text and the method byte for byte as before. The words are in both: the text ", without N tokens of messages with no model" before "(OpenRouter prices, ...)" and the method's tail; the Fact stays inferred. The tokens left out are never priced, never guessed from Agent.model, never added to a model. A usage that is not a usage value while byModel is known gives "cost unknown" with the usage's reason. A model with tokens and no price still gives "cost unknown" and no note (no partial sum as the total). On real local data every record has a model id (agent-tokens guide, Measured), so N is 0 there: test with made-up pairs, never claim a real example.
4. Method of other engines and our method (universal). The note says "messages with no model": do not name `<synthetic>`, a model, a role, a label or an engine in page text or code lines; the engines note is the only sentence about other engines and names none.
5. Re-render (flicker, stale-state). The cost cell is a keyed group (`keyOf('r', 'cost')`); adding the class `cost` must not change the key, and a longer text must patch only the cost text node. A demo Run's report has one cell fewer: the keyed list drops nothing else. Run web-u4 'a snapshot with the same numbers writes nothing ...' and the two flicker tests (lines 877, 2201) unchanged.
6. Timers and listeners. ensurePrices stays the only caller of `fetchJson('/api/prices')` (one occurrence); no setTimeout, setInterval, addEventListener, storage or innerHTML between 'function ensurePrices' and 'function costHtml' (web-u4 2848-2858). A failure is kept, no retry.
7. Escaping. The cost line goes through `fact()` and `esc()`; a model id such as `<img src=x onerror=1>` or `__proto__` in byModel, with usage larger than the split, must still draw as text (extend web-u4 'what comes from the run or the server is text ...' with a left-out pair).
8. CSS (c). Do not "fix" it by editing `.report .v` (every cell would change). `.report .cost .v` has three classes and wins over `.report .v` whatever the order. A cost cell whose text is "cost unknown: <reason>" or loading sits inside the same `.v`. The test reads web/style.css, takes the selector of the rule that sets 13px and 600, runs it with the fake DOM over a booted page (#report has class `report`) and requires exactly one match: the cost cell's value element, not the usage cells or the engines note. [weak-test]: on a throwaway copy set the class back to `cell-r wide` (or rename `.cost` in the css) and confirm the test goes red.
