## Rules that bind
- Contract section 4, GET /api/search: "over the loaded runs' models only (run name and description, agent prompts, results, activity summaries and texts, log lines); one result per field, around its first match; case-insensitive with Unicode case folding (per code point; dotless i folds to i, a known limit); at most `limit` results (default 50, max 200) and a time budget of 500 ms; over either, `more: true`. Read-only." Shape `{ results: [{ runId, agentId?, field, excerpt, start, end }], more }`. The contract already says it (08392c7); docs are not yours.
- Contract section 2: Fact `unknown` carries a `reason`; Agent.activity is "last 50"; Run.logs is "final only; unknown while running". Section 4 P1: a run listed with `loaded: false` has no transcripts read.
- AGENTS.md: "Never invent data. A value the source does not provide stays `unknown` with a reason."; "The visualizer only observes"; wfviz is universal: no role, label, phase, node code or file name of our method in src/, web/, bin/ (test/integration/universal.test.mjs scans code lines for /\bcodex\b/i, `dev-graph`, `docs/guides` and our role words as string literals); Node >= 20, zero dependencies; "Write only the files your node owns". graph.md section 9: "stop only the processes they started, by PID"; a node whose spec changes what other tests assert owns those tests.
- Choices recorded for the node note: (a) the highlight is a `mark` element between two text nodes (createElement, createTextNode), not a Range or CSS.highlights: the fake browser has no createRange and no HTML is parsed either way; (b) a row shows an agent's label only for the run on show, else the agent id, because the answer has no label; (c) a click on a run-level field (name, description, log) opens the run (when it is not on show), closes the drawer that is open on it (closeDrawer(); the drawer is position: fixed with z-index 10 and would cover the notice, which is in normal flow; this is the state right after a click on an agent's result) and puts the field and its excerpt in the notice #search-hit under the header ("search hit:", then "<field text> of <run name>", then the excerpt with the match in a mark element, all as text nodes): the answer has no line number and Run.logs shows only as the last 3 lines in the run head, so the notice shows only what the answer gives (the excerpt of about 120 chars: not the whole line, no position) and the run's description, which no other part of the page shows, can be read there; the notice ends on its close button, on Esc in the search box (clearSearch), on a change of run (selectRun without keepDrawer) and on a click on another result; (d) a log line is a field, an activity entry gives up to two.

## Traps
1. Scan scope. Only runs that pass `visible()` and `isLoaded()` (a missing `source` counts as visible; no loader means all loaded), from store.listRuns() then getRun(id) one at a time; never loader.load. A null or throwing getRun skips the run (onError), never a 500. Stand-ins (helpers.mjs makeRun, makeAgent) have no prompt, result, logs or description: nothing to search. Iterate Object.entries(run.agents), not `order`; an agent id `__proto__` is a key like any other (probed: works).
2. Never invent. Search a Fact only when prov is not "unknown" and the value is not null (a string as it is, else JSON.stringify(v, null, 2) as the drawer shows). Never a `reason` or `method` (the word "unknown" would match everywhere), never labels, ids, tool names, Run.result, edit inputs. `agentId` is omitted, not null, for run-level fields. No result count is invented: "more results not shown" has no number.
3. Folding. Per code point, c.toUpperCase().toLowerCase(); final sigma and sigma are equal, U+00DF is ss, U+0130 is i + U+0307, U+0131 is i. A folded index is not an original index: a match must start and end on a whole original character (query s misses inside U+00DF, ss finds it, i misses U+0130, a lone surrogate half misses an emoji). The same-length shortcut is valid: no code point folds shorter (scanned on Node 26). Listed limits: no locale rules, no normalisation (precomposed and decomposed e-acute differ). Tests carry each case with start/end read back against the original.
4. Excerpt. About 120 chars, always the whole match, cut at characters (never inside a surrogate pair), no ellipsis (it would shift the offsets); 0 <= start <= end <= excerpt.length and excerpt.slice(start, end) is the matched ORIGINAL text. A match near either end of the text shifts the window; a match longer than 120 makes a longer excerpt.
5. limit, more, budget. limit: digits only, below 1 or repeated is 400, above 200 is 200; `more` is true only when a further match exists (exactly `limit` matches is false); q empty, absent or repeated is 400 and is not trimmed; GET only (405 with Allow for HEAD and POST), exactly two path parts, the Host check applies. The clock starts before listRuns and is read before every run, agent, field and activity entry; over means elapsed > 500 (exactly 500 is not over); a stop keeps the results found. Test both sides with a fake clock. The scan is synchronous and the clock is not read inside one field: 5 MB of U+00DF in one field took 257 ms (1 MB 41 ms, ASCII 3 ms), so one huge field can overshoot; list that as a limit, do not make the scan async. foldCache holds single characters (at most 4096), no run data; nothing else is cached, no timer or listener per request.
6. Web escaping. A result becomes DOM only through createElement, createTextNode, textContent and setAttribute (title); highlightParts gives before, match, after and, for offsets that are not integers, negative, reversed, empty, past the end or inside a surrogate pair, the whole excerpt unmarked, never a throw. Test with `<img src=x onerror=1></mark>&amp;"'` as excerpt, agent id, run name and field, and count the elements the fake document made (no img element, one mark element per row). The section's own comment contains the word "html": a test that forbids html, innerHTML, setHtml, insertAdjacent and outerHTML in the section reads code lines only, or the comment is reworded.
7. Timers and requests. One debounce timer (250 ms) cleared before a new one, on Esc and when it fires; a newer query aborts the older one; a late answer of an aborted or superseded query is never drawn even when the fake fetch ignores the signal; an abort is not a failure; empty or space-only text asks nothing and clears; the text sent is the text typed; a failure says "search failed: <reason>", not "no results"; an answer with no result and `more: true` (the page asks with no limit, so the server's 500 ms budget ran out before a match: the review measured it on the real ~/.claude/projects, 43 runs, first query after start, 561-595 ms, the same query again `more: false`) says SEARCH_CUT_TEXT ("search stopped at the time limit, no result yet: try again"), never "no results", and the same answer with `more: false` says "no results". One AbortController per request (made when the timer fires), dropped when it settles; none per keystroke. The query is not written to the hash, localStorage or the picker's `q`, and run snapshots do not refresh the results.
8. Click and keys. Rows carry none of data-agent, data-result, data-run, data-unit, data-view (the page's one document click handler would take them). Click: clear the notice, select the run when it is not on show or a replay is on show, await it, check state.runId. A result of a run's own field (no agentId) then closes any open drawer (closeDrawer(): an agent's, or the run result's; it ends the drawer target too) and shows the notice (trap 10); it opens no drawer, and the notice is never shown with a drawer open on the run. For an agent: check that the run has the agent (one it lacks does nothing), openDrawer, and make the section (data-sec prompt, result, activity) a target, `state.drawerTarget = { agentId, name, at }` with `at` the drawer's scrollTop, applied at once and again by `applyDrawerTarget()` at the end of every `renderDrawer()` (the transcript read grows the Changes group above Result, Prompt and Activity from a one-line "loading..." to thousands of px, a snapshot can move it too): each apply is `showDrawerSection` (scrollToShow, one scrollTop write on #drawer when the section is not on show, never scrollIntoView) and then `at` is read back. The target ends when the drawer is closed (closeDrawer), the run result's drawer is opened (openResultDrawer), the drawer shows another agent, or when `#drawer.scrollTop !== at` (the user scrolled; the page does not scroll it back). No listener, timer or storage is added for it. The tests give the fake browser a layout that follows the DOM (every `.diff` block of the Changes group is 900 px) and require the section on screen after the transcript read, after a snapshot that moves it again, and not moved after a user scroll, after closing, after another agent, after the run result's drawer. Esc in the box clears text, timer, request and results and stops there (the drawer stays open); with an empty box and no results it falls through to the page's handler; ignored while e.isComposing. Do not write input.value back while the user types.
9. Re-render. Results are patched by key (listOf, lib.js patchList): a result that stays keeps its row element, scrollTop of #search-list and focus; the results of the last query stay while a newer one waits. The test uses the fake document's mutation records: after a second answer that shares rows, no node is removed and re-added with identical content.
10. Honesty on screen. The run name comes from state.runs (a Fact, else the run id). When the list has runs with `loaded === false`, one line says they are not searched (a run with no `loaded` counts as loaded). Never show a label for an agent of another run. The notice of a run's own field shows the field text, the run name and the excerpt as the answer gave them, never a line number, a count or more of the line than the excerpt, and is shown only after the drawer on the run is closed (a click on the run's own field with an agent's drawer open on the run leaves the drawer closed and the notice on screen; a drawer the user opens later from the page can cover it again: that is the user's own click, the notice has its close button).
11. Universal. The field names are the server's closed set (name, description, log, prompt, result, activity-summary, activity-text); an unknown one is shown as written. No role, phase, label pattern or file name of our method in code; test data uses neutral words (fixtures' alpha and probe are data, the code asserts nothing about them).
12. Read-only. No endpoint writes, loads or starts anything; the handler reads the store and answers.
13. Look. The header wraps (flex-wrap). Measure at 800 and 1228 px in headless Chrome over CDP (precedent evidence/tmp/run-history-geometry.mjs; start wfviz with --since Infinity so runs are loaded, and with a 120-char excerpt without spaces): box and panel inside the window, no horizontal scroll of the page, the excerpt wraps, the list scrolls inside the panel, `[hidden]` hides the flex panel, the picker's panel and the search panel are not open together, the drawer (z-index 10) is not covered after a click. Measured 2026-11-12 on the final code in headless Chrome over CDP (scratch script, not in the repo: wfviz on a copy of fixtures/claude-projects with six Write calls of 60 lines on the agent whose prompt contains "Run these Bash commands", --since Infinity): after a click on its prompt result the prompt is on screen at once and 1.5 s later, after the transcript read grew the Changes group from 15 px to 1789 px (1228x500: scrollTop 301 then 2075, section top 448 of 500; 1228x800: scrollTop 1 then 1775, section top 748 of 800; 800x800 the same as 1228x800), and a user scroll to 5 is left at 5 by a later render; on the code before the fix the prompt was off screen after the read (1228x500: scrollTop stayed 301, section top 2222; 1228x800: scrollTop 1, section top 2522). The notice (#search-hit, a flex row with flex-wrap, `overflow-wrap: anywhere` on its text, the close button last): at 375, 800 and 1228 px wide it spans the window (left 0, right = the window width), scrollWidth equals clientWidth, the page's scrollWidth equals the window width, a 120-char excerpt without spaces and an excerpt of 24 words wrap inside it (height 27 px at 1228 for one line and 44 px for the words; 44 and 60 px at 800; 79 px at 375), the close button's right edge is inside the window (1214 at 1228, 786 at 800, 361 at 375), and the phase bar starts at the notice's bottom edge.
