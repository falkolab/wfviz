# Node guide: demo scenarios (unit demo-scenarios)

Read with docs/guides/common.md. The spec (items 1-6) is in the node task; this file says what binds, what you may break, where it is easy to go wrong, and how to check. Tests are named, not numbered by line.

## Rules that bind
- docs/contract.md §1 "Replay": the source "emits the same RawEvents with `src: "replay"`, every value unchanged (ts included...)"; delay "`(key₂ − key₁) / speed`, capped at 2000 ms (default speed 4, `--speed` 0.25..100)"; "Replay never mixes with real or demo events; at the end the run stays as read (its final file included). A run id is looked up under `--root`." §1 rules: "a source never invents values; a missing field stays missing". §2: `source: "real" | "demo" | "replay"`. §5: the store gets only events of its own mode.
- contract intro: "wfviz is universal"; no role, label, node code or file name of our method "may be required or hard-coded" in src/, web/, bin/. AGENTS.md, Hard rules: "Never invent data"; "Do not use API, hooks or log formats that are not documented or observed"; "The visualizer only observes"; "Demo data never mixes with real data"; "Write only the files your node owns"; no git commit, stash or reset; zero npm dependencies; "No global config changes, no plugin installs, no publishing".
- graph.md §9: "A node's gate can block on a test outside its owned paths that asserts the old contract"; "A judge that upholds a wrong contract is right; contract defects must be escalated to the orchestrator"; a directory given to `node --test` on Node 22+ needs an index.js shim (every test/*/index.js loads each *.test.mjs, so a new file needs no list). Only high and medium findings send work back.

## Traps
- Schedule key. "First/last transcript record ts" comes from the events readRunDir returns: kinds agent.prompt, agent.activity, agent.structured of that agentId, min and max ts. Do not re-read files. "When known" = the agent has one of those; else the journal event keeps its own ts. run.script, run.launched and agent.meta carry file times too and keep them: never guess a key.
- The literal rule has visible consequences, measured on wf_6509ce25-20a (31 events): run.final lands at index 23 (0-based), then 5 agent.meta, run.launched and run.script (file times 1.1e6 ms later, delay capped), so phases and script arrive after the final file; a result sits before its own agent's last transcript event (journal comes first in reader order). Implement it literally, in one small `scheduleKey` function, and put the numbers and a proposal in the note (key file-time events by the run's first key or the agent's first transcript key). Reviewers and judge escalate this, they do not send it to the fixer.
- Delay: divide first, then cap (speed 0.25, gap 1000 ms gives 2000, not 4000); the first event has delay 0; sort by (key, reader index) explicitly. A non-finite ts must still be emitted (total equals readRunDir's): decide (recommended: key of the previous event), test, name in the note.
- Values: emit `{ ...ev, src: 'replay' }`; do not mutate readRunDir's objects, rewrite ts, prov or data, or stamp the wall clock. Test deepEqual against readRunDir after removing src. Speed: clamp numbers to 0.25..100; for NaN, 0, text decide (recommended TypeError), test, name it.
- Stale rule. Measured: `createStore()` with replayed events (a day old) gives status unknown "no file activity for 1390 min (limit 30 min)" and unknown agent states until run.final; `createStore({ staleMs: Infinity })` gives running. Replay mode needs the second form (check that its timer does not leak). Run.source precedence: demo, then replay, else real; replay mixed with another src is reported with the existing "several sources" warning, not dropped; decide the resulting source, test, name it.
- Timers and listeners. One pending timer at a time, kept in a variable; stop() clears it and bumps an epoch, idempotent, also while readRunDir is still being awaited (start must then schedule nothing), and a later start() works; check the stopped flag before every emit, because onEvent may call stop(). Inject `timers` like demo.mjs does and test that pending timers are 0 after stop() and after the last event. No loop, no restart at the end (the demo loops, replay must not). A readRunDir failure makes start() reject (bin exits 1); invent no warning event.
- Lookup. `--replay` takes a run directory `<session>/subagents/workflows/wf_…` or a runId. Check that shape (basename wf_*, parents `workflows`, `subagents`), take the session as three levels up, else a clear error. For a runId walk `<root>/<slug>/<session>/subagents/workflows/` and compare the argument with the entry names; never join it into a path first (`../x` must not escape root). No --since window (fixture files are old). Two matches: an error naming both; none: an error naming root. Exit code 2, one `wfviz: …` line on stderr, empty stdout. loadParts errors go to main().catch and exit 1 (kept for a missing module), so the unknown run needs its own path (shutdown(2, message), after handlers exist).
- CLI. args.mjs stays pure (no fs, no process). Decide, test, name: directory or runId when both fit (recommended: existing directory first); --speed without --replay (recommended usage error); --speed outside 0.25..100 (recommended: CLI rejects non-numbers, <= 0 and Infinity, the source clamps, --help says so); --root with a directory and --since with --replay (warn, as for --demo); the listening line `(replay)`.
- Server. createServer: mode union, TypeError text, JSDoc, `expectedSource` 'replay'. The "store accepts only replay events" check is guardedSink in bin (not exported, not in src/server): test it through the bin process with a stub replay source that also emits a claude-fs and a demo event (makeStubTree in bin.test.mjs is local: copy the idea). Fake mode (WFVIZ_TEST_FAKE): decide what replay does. No second snapshot throttle: bursts at speed 100 meet the existing one-per-second `run` rule.
- Escaping. Echo a user-given runId or path in an error through JSON.stringify (a newline or control character must not forge a second line on stderr). README prompt lines carry the args as one-line valid JSON, with target paths free of spaces, quotes, backticks, `$` and backslashes (workflow A refuses them); quote shell paths.
- Method coupling. Nothing in replay.mjs, args.mjs, bin or the model may name our labels, node codes, gate or fixture run ids; wf_6509ce25-20a appears only in package.json and demo/README.md.
- Workflow demo-free-labels. Labels without `:`, without `#` and without "round <n>" (the three things parseLabel reads), unique per agent. The target-b files are 01-overview.md … 05-support-faq.md; "notes.md" in the spec is an example. Bound the agent count by a constant derived from the cap of 8 (readers + summary + final check), refused up front like research-fanout does, not by files.length. Use only agent() options seen in the repo's scripts (label, phase, schema, model, effort); read-only is a prompt rule, invent no tool option. Give every agent an explicit `phase` equal to a meta title; use every declared phase. Model "haiku".
- README. `--replay` replays ONE run (contract), so `npm run demo:replay` replays wf_6509ce25-20a (completed) with `--root fixtures/claude-projects --speed 8`; give the second saved run wf_26eb8d70-5c4 (failed) its own command; do not call it "runs" or add a multi-run mode. Take A's and B's args from the header comments of their scripts, do not paraphrase. A edits its target and refuses a targetDir holding `.wf`: show `cp -R fixtures/target-a <new dir>` and say new dir for each run, never fixtures/ itself. Say wfviz is started first. For recording say only what you saw on this Mac in the Cmd+Shift+5 toolbar (as far as known it has no record-window button; recording a window means Record Selected Portion around it); mark anything unchecked. Give no cost figure unless copied with its source from docs/cost-report.md. State what each scenario shows only as far as contract §2 says: loop with judge and rounds (role × unit matrix), fan-out, fallback matrix (phase × agents).

## How to check each item by hand
Start with `--no-open --port 0 --idle 0`; read output by curl and `node -e`, never open a browser.
1. Pure schedule on wf_6509ce25-20a: 31 entries, every agent.started before its agent.result, max delay <= 2000 at speed 0.25 and 100, run.final before the file-time events (the consequence above), same count as readRunDir.
2. Source: `node -e` with createReplaySource at speed 100 collecting events: src all "replay", the rest deepEqual to readRunDir; stop() mid-run, then wait 3 s: no event, process exits by itself.
3. Model: apply the events with src replay to `createStore({ staleMs: Infinity })`: source "replay", running before run.final, completed after, equal to the direct read except source; with `createStore()` see the unknown status (the trap).
4. Server and bin: `node bin/wfviz.mjs --replay wf_6509ce25-20a --root fixtures/claude-projects --speed 100 …`; `curl -N /api/stream` first frame `hello` with `"mode":"replay"`, `/api/runs` source "replay", after 2 s status completed with 5 agents; SIGINT: exit 0 within 3 s. Errors, each exit 2 with empty stdout (`echo $?`): `--replay x --demo`, `--replay wf_nope`, `--replay ../x`, `--speed 0`, `--speed abc`, a directory that is not a run directory. `--help` lists --replay and --speed.
5. Workflow: `node --test test/workflows/demo-free-labels.test.mjs`; by hand dry-run it and print labels and phases: no `:`, parseLabel gives unit null for each, at most 8 agents, 2-3 phases all used. A live run needs the Workflow tool, which the orchestrator starts.
6. README: run each command with `--no-open` added (`npm run demo:replay -- --no-open --idle 0`) and see the listening line; `--demo` prints `(demo)`.
Before finishing run `node --test test/` once: all pass, 0 skipped.
