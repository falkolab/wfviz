# Node guide: run start and replay lookup (unit run-start-and-lookup)

Read with docs/guides/common.md. [stale-test] applies (every test that asserts the old order or the old lookup is named below with its new numbers), [guide-defect] applies (every number below was measured on 2026-11-10 in a throwaway copy of the repo with the three changes made, and the last line names the tests that must go red). [flicker] concerns web/, which is not yours; its model-side corollary is in trap 4. [stale-state] applies to the launcher (bin/wfviz.mjs is yours): the first snapshot of a replay is the Run after the first step, never the Run after run.script alone (trap 10); a test is never loosened to accept null or unknown there. The spec is in the node task. Make any throwaway copy in a directory named after this node: a scratchpad directory called `copy` was replaced by another agent's smaller tree while I measured.

## Rules that bind
- docs/contract.md, intro: "wfviz is universal"; no role, phase, label, node code, file name or result shape of our method "may be required or hard-coded" in src/, web/, bin/ (test/integration/universal.test.mjs scans code lines, comments excluded).
- contract section 1, rules: "a source never invents values; a missing field stays missing". Section 1, Replay: events are re-emitted "every value unchanged (ts included ...)", "Only the emission schedule is computed"; run.script and run.launched "are keyed by the smallest key of the run's other events, so a replay begins with them"; "ties keep reader order"; the delay is "(key2 - key1) / speed" capped at 2000 ms; "The replay endpoint (section 4) looks its run id up under the root only, never as a path relative to the process directory".
- contract section 2, Run: run startedAt is "the final file's start; without it the earliest agent start (inferred); only when no agent has a start, the script file time (inferred ...); else unknown". Fact: unknown has a `reason`, inferred has a `method`. Section 4, replay endpoint: files are "looked up and read before the stream starts"; files not found or no events is a 404 JSON `{ error }` and no `hello`.
- docs/guides/common.md [stale-state]: a value that a later record of the same synchronous hand-over will replace (the script file time before the first agent record, a status before the first event) is never published as a snapshot; the first publish waits for the whole first step; the test records the first frame actually sent and requires the final values in it (startedAt from the first agent start, a known status). Contract section 4: replay snapshots have the same throttle as /api/stream (the first at once, then at most one per second per run).
- AGENTS.md, Hard rules: "Never invent data"; "Inferred values carry `prov: "inferred"` and a `method`"; "Do not add handling for formats not observed in `sources/event-sources.md`"; "Write only the files your node owns"; no git stash, git reset or destructive command; zero npm dependencies. graph.md section 9: "Workflow agents must stop only the processes they started, by PID" (start wfviz with --no-open, stop it with kill <pid>); "A node whose spec changes behaviour that another node's tests assert must own those test files".

## Traps: run start (src/model/reduce.mjs, reduceDetailed, run-level facts)
1. Order: final startTime (finalFact, as now); else the smallest agent start that is not coarse (an agent startedAt whose `method` is not 'journal-event-ts'; a final-prov start has no method and counts; a value that is not a finite number is skipped; a final file without a numeric startTime does not count, the next step applies), method exactly 'earliest-agent-start'; else, only when no such start exists, the smallest coarse one with a method that says so, e.g. 'earliest-agent-start (journal file times, coarse)' (the wording of the agent duration, reduce.mjs:505); else the script file time, 'script-file-time'; else unknown with a reason that names the final file startTime, the agent start and the script file time. Math.min of an empty list is Infinity and of null is 0: guard.
2. Take nothing from lastTs, the run.launched ts or event order, and nothing but the agents' startedAt Facts. Do not parse a string startTime (all 34 are numbers; unobserved formats are not handled). The Fact keeps the keys { value, prov, method } and no others. Keep the two old method strings spelled as they are: web tests and the elapsed text ("inferred, <method>") quote them. Do not import infer.mjs for the coarse set; compare with the literal already used at :487 and :501.
3. Derived values need no code: Run.durationMs is the final's durationMs or unknown (never start-based), phases and order use agent starts, store.listRuns sorts by the run start (newest first, unknown last) and follows by itself, web/lib.js elapsedFact reads run.startedAt (not yours). Add a sentence to the header comment of reduce.mjs (Time paragraph) with the order.
4. [flicker] corollary: from the first transcript record to the event before run.final the start Fact must be deep-equal at every event (measured: constant), so it never repaints a cell; test it. The first snapshot of a replay already holds that Fact (trap 10).

## Traps: replay schedule (src/source/replay.mjs buildSchedule, scheduleKey)
5. Order of work: (a) keys of the events that are not run.script or run.launched by the existing rule, null when none; (b) floor = smallest finite one (never Math.min over nulls); (c) the two head kinds get floor, or their own ts when there is no floor; (d) the existing carry for events with no key; (e) sort by key, then heads before others at the same key, then reader order. Step (e) is more than "ties keep reader order": ties alone left a script that is last in reader order after the first agent events (18 of 35 runs); the spec says the heads go out first, in reader order. A run with no run.script (1 of 35) or no run.launched (5 of 35) has no head of that kind: nothing is added or invented, and it starts with its earliest other event. The delay rule is unchanged, so no wait is added; say in your note that you read the contract's "ties keep reader order" as holding inside each group.
6. scheduleKey(event, spans) is called with two arguments in tests: keep it working for every kind (a head kind returns its own ts without a floor) and take the floor as an optional third. buildSchedule must not write into events (tests check the same objects come back, src still 'claude-fs', ts still the file time) and the source keeps `{ ...event, src: 'replay' }`. Add no timer (zero-delay entries are not timers; a test counts them); stop() is unchanged. Rewrite the header comments "Schedule" and "Consequence of the literal rule" (now only agent.meta and a run.final read after the fact come late).

## Traps: the first snapshot of a replay (bin/wfviz.mjs: oncePerStep, announcingAfterStep, realReplays.open)
10. [stale-state] The server sends the first snapshot of a stream at once (queueSnapshot: no wait when the last one is a full window old) and builds the Run in that very call. The replay source hands the heads, agent.started and the first records of the first agent over in one synchronous step (delay 0, one key). Announced after each event, the first change is run.script alone: start script-file-time, status null/unknown, 0 agents, and the next snapshot comes only after the 1 s throttle. Rule: a replay's changes are announced after the step. In bin: `oncePerStep(fn)` returns a function that calls fn once in a microtask however many times it is called before; its `.now()` calls fn at once when a call is waiting. (a) realReplays.open: the replay store's onChange calls it for onRun (still only for the run's own id, still not after stop); the sink calls `announce.now()` before `onEnd()`: onEnd stops the stream, a microtask that runs after it is ignored, so without `.now()` the state of the last step is never sent (measured: a replay that is one step long sends no snapshot at all). (b) --replay on the command line: loadParts returns `announcingAfterStep(store)` (the store with onChange listeners called after the step, one pending call per run id; apply, getRun, listRuns, onEvent, eventsSince are the store's own) and the guarded sink applies to that same store. Not a timer (queueMicrotask), no change to src/server (not yours; its first-snapshot rule stays) and none to the replay source (zero-delay entries stay inline). The throttle still decides which later snapshots go out; the `run` frame order against `event` frames is now: the events of the first step, then the first snapshot.
11. Tests of trap 10 (never loosen: null/unknown is not accepted in the first frame, common.md [stale-state]): bin.test.mjs :892 (stub source, 8 events in one step: hello, 8 events, one `run` whose counter is 8, end; the Run built once); replay-endpoint.test.mjs :673 (both saved runs through the real bin at speed 100: the first `run` frame has startedAt value = the smallest transcript record ts of the run, prov inferred, method earliest-agent-start, status running/inferred, at least one agent; every later snapshot has the same Fact until the one with prov final, and no snapshot has script-file-time); bin.test.mjs :1114 (--replay on the command line, speed 4: the first snapshot a page gets, same assertions); replay.test.mjs :100 (strict first snapshot with the local wrapper). The two stub-tree tests that count snapshots keep their numbers (two snapshots, two builds) because the stub now has two steps.
