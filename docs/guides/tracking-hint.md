# Node guide: tracking hint (unit tracking-hint)

Read with docs/guides/common.md: [stale-state] and [flicker] (the notice is written once at load, never again), [stale-test] (two tests below), [guide-defect] (geometry is measured, not assumed). The spec (items 1-7) is in the node task; this file says what binds, what you may break, where it is easy to go wrong, and how to check. Tests are named, not numbered by line.

## Rules that bind
- docs/contract.md, intro: "wfviz is universal"; no role, phase, label, node code, file name or result shape of our method "may be required or hard-coded" in src/, web/, bin/. The prompt is advice for any workflow, never a requirement, and says nothing of how this project is developed.
- contract section 2 "Label pattern (inferred, never required)": `role:unit#tag`, "`round` comes only from `#r<n>`". section 3: "Recognition is by field names only"; the prompt may name only fields section 3 lists (`findings`, `file`, `line`, `severity`, `description`, `input`, `verdict`, `reason`, `tests`, `passed`, `failed`, `skipped`); the run total is "exactly one run-scope tests item". The sync test must slice the text between "## 3." and "## 4." (a whole-file search passes on `file` and `line` found anywhere) and match whole backticked names.
- AGENTS.md, Hard rules: "Never invent data"; "The visualizer only observes: no endpoint writes, stops or starts anything"; "Write only the files your node owns"; no git commit, stash or reset; ES modules, Node >= 20, zero npm dependencies. "Images and video": read the page as DOM text; never use the browser pane.
- graph.md section 9, "Two modes of tracking": the hint is "advisory"; an ordinary run is shown from its files, unchanged. Also section 9: "A node's gate can block on a test outside its owned paths that asserts the old contract."

## Traps
- Coupling. Names are compared as whole words split on - and _: no id or class that is impl, rev, judge, fix, test, accept, implement, review, reviewer or fixer (hint, hint-copy, hint-close pass). No comment with "item 3", "U2", "docs/guides", "graph.md", "AGENTS.md". The notice never reads state.mode, state.run or the run list. A dry run of the universal scans on the prompt (template literal, quoted string, joined array) found no hit: if a scan flags the fixed text, escalate, do not reword.
- Exact text. One exported TRACKING_PROMPT in lib.js; index.html holds no copy (`<role>` and `<unit>` would parse as tags, a `"` breaks an attribute); set it once with `box.value = TRACKING_PROMPT`, never through innerHTML or esc(). LF between lines, no leading or trailing newline, nested bullets indented two spaces; the task text is indented by the harness, strip exactly that. The test holds its own literal copy of the spec text, not the import compared with itself.
- Copy. Pure functions in lib.js: copyPath(nav) is 'clipboard' only if typeof nav?.clipboard?.writeText === 'function' (nav undefined, no clipboard, no writeText: 'select'); copyLabel(status) for 'idle', 'copied', 'failed' gives "Copy prompt", "Copied", "Copy failed - select the text" with U+2014 and one space each side (raw in web/ files like the DEMO banner; the test writes the escape text `\u2014`). Copy the constant, never textContent of a node. writeText returns a promise: handle rejection (no unhandled rejection) with the failure label and select the box. execCommand can return false or throw: failure label. Decide and name: no second path after a rejection (the spec lists two), the failure label also returns after 2 s.
- Timer. One setTimeout, in app.js (with the highlight and the transcript re-read the page has three; see the stale tests above), its handle in one state field (`state.hintTimer`), clearTimeout before a new one (two clicks in 2 s do not stack); it writes only the button text (setText). No interval, no timer on open or close.
- Storage. Reads and writes only through localGet and localSet. Only the exact value "1" closes: null, "0", "", "true", any text opens it (hintInitiallyOpen(storedValue), pure). A localStorage that throws, even on property access: the notice shows and closing still hides it. Decide and name what reopening writes (recommended: nothing).
- Steady. Static markup in index.html with the `hidden` attribute (the global `[hidden]` rule is !important, so a display rule cannot show it by mistake), shown once at load with setShown. No render function, SSE handler, snapshot or event touches it: `grep -n hint web/app.js` shows boot code and its own handlers only. Reopening toggles hidden only: the box value, selection and scroll are not rewritten.
- Keys and focus. Escape is a keydown listener on the notice (focus inside); call stopPropagation so the page's Escape handler does not also close the drawer or picker (decide, name, test that the drawer stays). Not modal: role="dialog", aria-label "Better tracking (optional)", no aria-modal, no focus trap, no focus move at load. Decide and name: focus goes into the notice when the header button reopens it, and back to the header button when the notice closes. Real buttons; the box is a readonly textarea with an accessible name. Add `textarea:focus-visible` to the focus rule (it lists button, input, [tabindex], summary). Close glyph: x or U+00D7 (the drawer uses U+00D7), aria-label "Close" either way.
- Click handler. The page's click handler matches data-agent, data-unit, data-view, data-run, data-result and data-tests-toggle: none of them on the notice or its buttons.
- Layout. The notice is the last child of `<footer id="log-pane">`, after `#log`; the pane is `position: relative`, so the notice is `position: absolute; right: 14px; bottom: calc(100% + 10px)`: its bottom edge is 10 px above the pane's padding box in every pane state (open, dragged to another --log-h, collapsed to its head). There is no `position: fixed`, no sibling rule `.log-pane.collapsed ~ .hint` and no per-state number. Measured in headless Chrome (rects), the 9 px between hint bottom and log top is the pane's 1 px top border: 1228x800 and 800x800 open hint bottom 601 vs log top 610; collapsed 753 vs 762 at 1228x800 (738 vs 747 at 800x800, where the header wraps). z-index 5: above the columns, below the drawer (10, `position: fixed`): an open drawer covers the notice and does not move it (name it). Width `min(420px, calc(100vw - 28px))`, max-width 420px. max-height `min(50vh, max(120px, calc(100vh - var(--log-h, 190px) - 100px)))`: half the window, and where the window is short or the log tall at most the room above the log less 100 px (about the header and the phase bar), never under 120 px; overflow-y auto. Measured notice heights: 272 at 800 high (content 270, no scroll), 210 at 500 high (scrollHeight 270, clientHeight 208), 120 at 400 high (clientHeight 118). Known limit, measured: the 100 px is an estimate, so in small windows the notice can reach into the header and the phase bar (#steps): 1228x500 top 91 vs phase bar bottom 88 (clear); 800x500 top 91 vs phase bar bottom 122 (header 79 px high, covers 31 px of the phase bar); 600x400 top 81 vs header bottom 109 and phase bar bottom 152. It never reaches the log head or the pane. Colours from tokens, no hex, `font: inherit`, textarea resize none. Append the rules at the end of style.css (no earlier `.log-pane`, `.log` or `body` rule). Wide or tall content: title and line wrap (overflow-wrap: anywhere), the box scrolls.

## How to check each item by hand
Start `node bin/wfviz.mjs --no-open --port 0 --idle 0 --root fixtures/claude-projects --since Infinity` (add `--replay wf_6509ce25-20a --speed 20` for replay); never `--demo` in place of real data; stop only the PID you started. Read pages by curl and DOM text. Geometry (above the log header, away from the drawer, 50vh, widths 800 and 1228, log open and collapsed, a 500 px high window where the notice scrolls, and against the header and the phase bar at 1228x500, 800x500 and 600x400) is measured by you in headless Chrome over CDP (/Applications/Google Chrome.app, its own user-data-dir, not the browser pane): rects of #hint, #log-pane, .log-head, header, #steps, #drawer. Only paint is left to the ui-check as "unchecked".
1. index.html (grep): role="dialog", aria-label, title, the line, the box, "Copy prompt", the close button, the header button "Tracking hint".
2. Fake page: copyPath({}) is 'select', copyPath({ clipboard: { writeText() {} } }) is 'clipboard'; a click with a recording clipboard: writeText got exactly TRACKING_PROMPT; "Copied", then after the recorded 2000 ms timeout "Copy prompt"; a rejecting writeText: failure label, no unhandled rejection.
3. Storage "1", null, and getItem and setItem that throw: hidden, shown, shown, and close does not throw. In a real browser: close, reload (hidden), header button (shown).
4. Boot on REAL, DEMO and REPLAY hello, with and without runs, then 20 `run` and `event` frames: writes to the hint elements are 0 after boot; timers and document listeners do not grow.
5. Mutate one character of the constant: the text test is red. Add "severities" to the prompt: the sync test is red. parseLabel('writer:intro#r2') gives role writer, unit intro, round 2 (import src/ read-only).
6. Escape inside the box hides it and leaves an open drawer; Escape outside leaves the notice.
7. `node --test test/server/web-hint.test.mjs test/integration/universal.test.mjs`, then `node --test test/` once: 0 fail, 0 skipped, 0 todo, except the two tests named above until the orchestrator changes their counts.
8. Geometry, once, from the rects: at 1228x800 open the hint bottom is 601 and the log top 610, collapsed 753 and 762; the notice never overlaps the log head; at 500 high it scrolls inside itself (scrollHeight above clientHeight); with the drawer open the drawer covers it. The overlap with the header and the phase bar at 800x500 and 600x400 is written down as a number (31 px and more), not called fine.
