## Traps
1. Exact text. Take it byte for byte from the spec in workflows/nodes/hint-text.mjs (check 1 below), not from the task text, whose lines carry a harness indent of two spaces. Six lines joined by LF; 666 characters; ASCII; the "x" in "role x unit" is a plain letter; quotes are straight; "recognised" is the British spelling; line 1 starts "wfviz," with a comma. No trailing space, no final newline. Measured: no METHOD_NAMES hit, no node code, none of the script test's banned words (fetch, exec, net, import and so on) in the text, and no line starts with a listed verb.
2. Quoting in the script. The fifth line holds an apostrophe ("workflow's"): write that element in a double-quoted string or escape it, and the others in single quotes; a backslash that survives into the output breaks exactness. Build the output only with JSON.stringify of the object, never by joining strings, so quotes and line feeds in the text are escaped. Keep one process.stdout.write, no console, no import and no stdin read (the script test greps for import, require, node:, process.stdin, process.exit, console and others, and counts exactly one process.stdout.write; it does not grep for timers or listeners). Keep the one listener the script has, `process.stdout.on('error', () => {})`, and the try/catch around main: without the listener the test "exit code is 0 when the reader of stdout has gone away" goes red (measured 2026-11-12 on a temp copy). Add no timer and no other listener. The header comment may stay.
3. Do not invent or widen claims. The text is approved wording: do not reword it, even where a reviewer finds it broader than the contract ("run totals" is, in the model, only the one run-result `tests` item; log lines come only with the final file). Report that as a low finding for the orchestrator; it is not a fixer round. The README adds no statement about what wfviz shows beyond the text itself, and nothing about live updates.
4. Coupling. The README and the new test literal must not contain, even inside a longer word, guide, judge, fix, reviewer, implement, dev-graph, graph.md, AGENTS, docs/ or a node code like U2 (watch "prefix", "suffix", "implementation"). Run the scan on plugin/ after every README edit. "role" and "phase" are generic words in the text; the test keeps the `<role>:<unit>` check.
5. The new imperative test (spec 3). Its list is its own literal: Label, Pass, Return, Put, Use, Write, Add, Make. For each of the six lines, remove a leading "- ", take the first word and compare whole words, ignoring case, so "Labels" and "Passed" do not count and "wfviz", "Agent", "A", "JSON", "Run", "log" pass. Put it beside the "text:" test in hint.test.mjs and give the failing line in the message. It checks two texts, each of six lines: the test's own EXPECTED_HINT and the text the script really prints (run as a child process, additionalContext parsed from its JSON). It fails on the old script (first words Label, Pass, Return, Put); on the old script the test's own copy passes, so the script-output half is what turns it red.

## How to check each item by hand (no Claude session needed)
Set `T=$(mktemp -d)` first.
1. Text: `node -e "import('./workflows/nodes/hint-text.mjs').then(({default:n})=>{const s=n.spec,a=s.indexOf('\n---\n')+5;process.stdout.write(s.slice(a,s.indexOf('\n---\n',a)))})" >"$T/want.txt"`, then `node plugin/scripts/session-start.mjs </dev/null | node -e "process.stdout.write(JSON.parse(require('fs').readFileSync(0,'utf8')).hookSpecificOutput.additionalContext)" >"$T/got.txt"; cmp "$T/want.txt" "$T/got.txt"` (silent when equal; on the old script it says "differ"). `wc -c` gives 666; `grep -nP '[^\x00-\x7F]'` on plugin/, test/plugin/ and this guide is empty.
2. README: `node -e "const f=require('fs');process.exit(f.readFileSync('plugin/README.md','utf8').includes(f.readFileSync(process.argv[1],'utf8'))?0:1)" "$T/want.txt"; echo $?` prints 0; `grep -c "factual statements" plugin/README.md` is 1; `grep -n "imperative\|prompt-injection\|most of its lines\|approved as written\|shows it to you" plugin/README.md` is empty; the first paragraph and the debug-log sentence are still there.
3. Tests: `awk '{sub(/^- /,"");print $1}' "$T/got.txt"` lists wfviz Agent A JSON Run log() and none of the eight verbs; `node --test test/plugin/` gives 25 pass, fail 0, skipped 0, todo 0; the same run on a temp copy of the tree whose script is `git show HEAD:plugin/scripts/session-start.mjs` is red in 7 tests (measured 2026-11-12): the exact-output test, the hooks-config test, the imperative test and four tests that compare the printed text with EXPECTED_HINT (stdin kinds, switch on, WFVIZ_TRACKING_HINT, unusual environment); the "text:" test checks only EXPECTED_HINT and stays green. With the old README and the new script, the README test is red.
4. Nothing else changed: `git diff --stat -- plugin test/plugin` lists only the owned files above (a whole-tree `git diff --stat` also shows other nodes' uncommitted work: src/server, test/server, docs/guides); `git diff -- plugin/hooks plugin/.claude-plugin test/index.js` is empty; the output keys, matcher "startup", off switch and exit 0 tests are untouched and green. An empty diff on plugin/scripts is a `missing-implementation` blocker.
5. Other suites as in the baseline note (the server suite takes about 110 s: run it in the background and read its output file), and `node --test test/integration/universal.test.mjs`.
6. Unchecked, write "unchecked" in the note: that Claude Code fires the hook in a new session and that Claude uses the context (needs a session with the plugin loaded, the user's step). Never run claude --plugin-dir, install, enable or marketplace add.
