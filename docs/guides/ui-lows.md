## Traps
1. Status (flicker, stale-state). The cause is the `setShown(status, status !== '')` line: `hidden` takes the line out of the layout. One element, never `hidden` while the panel is open, text only through setText; do not make it a row of hitList, rebuild the panel or use innerHTML. Reserve one line with a min-height equal to the measured one-line height (27.4 px; write it in em plus the 12 px padding so it follows the font, then measure): a smaller value leaves the empty state shorter than "searching..." and the rows still move. Do not clip the long texts (SEARCH_CUT_TEXT is 58 chars, a failure reason has no limit): no nowrap, no ellipsis, no fixed height; they wrap at 375 px but only occur with an empty list (a failure clears the results), so no row is on show to move. An empty reserved band above the rows is the intended result. Keep role="status"; #search-note below the list stays as it is.
2. Notice and hint (layout). This guide chooses: the hint closes. When the run-level branch of openHit shows the notice, call `setHintOpen(false)` (through one small function in the tracking-notice section). Never call closeHint(): it writes `hint.closed` (the user's own close, kept for the next load) and moves focus. A hint closed by the notice stores nothing, is not reopened when the notice closes, and a fresh profile shows it open after a reload. A profile with `hint.closed` = '1' has it closed already: nothing is written. An agent-level hit shows no notice and leaves the hint alone. Stacking instead needs `position: relative` and a z-index of 6..9, and at 375x700 the notice (245..290) would cover the top 61 px of the hint (229..501), its title and its close button, so the hint could not be closed; that is why this route is not taken. The user opening the hint from the header while the notice is on may cover it again: their own click, as with the drawer. The new function reads nothing of state.run, runs, runId, mode, log, view, picker (web-hint forbids it in that section).
3. Run cost count (invented value). From Run.agents with Object.entries (an id `__proto__` is a key like any other): n is the entries that are objects, k those with `usageValue(agent.usage) !== null` (an all-zero known usage counts; an unknown Fact, no usage, `{}` do not). Never parse the "(k of n agents; ...)" text of totals.usage. No agents object (the web-tokens `runOf` stand-in) gives n = 0: no "k of n", no "0 of 0". k = n: text and method byte for byte as today. k < n: `~ $X for k of n agents` straight after the amount, then `, without N tokens ...` if that holds too, then ` (OpenRouter prices, fetched HH:MM)`. The method gets one sentence, placed before the "without N tokens" tail so the existing `endsWith('; without N tokens ... not priced)')` checks hold: the other n-k agents have no usage in the run files, so they are not priced; right for n-k = 1; no cause named ("still running", "no transcript": the reason is each agent's own usage Fact) and no agent id or label in it. The amount is unchanged (totals.byModel holds only agents with usage). The rule is `k !== n`, so k = 0 with n > 0 reads "0 of n agents" without a special case. Carry the count in the runCost result like `leftOut` (absent when equal) so costView builds text and method from one place; the Fact stays inferred. agentCostView does not change: test it byte for byte. Patch only the cost text node; the cell key (`keyOf('r', 'cost')`) and its classes stay.
4. agentNeedsPrices. False for no Run (undefined, null, not an object); `{}` or a Run with no source stays true (cost-leftovers trap 1). Leave isDemoRun alone: web-tokens pins isDemoRun(undefined) false and usageCells and drawerItems use it. "No cost is shown" must follow the same gate, or a cost row that is drawn while ensurePrices is never called reads "loading OpenRouter prices..." forever: one pure lib.js predicate, "a Run object that is not demo", used by agentNeedsPrices and by the cost row (drawerItems) and cell (usageCells) conditions. drawerItems reads run.agents[id], so the page never has no Run: test the Run-less case in lib, not in a booted page.
5. Coupling. No role, phase, label, node code, file name or engine name of our method on any code line of web/ (a trailing comment counts; universal.test.mjs scans src, web, bin; web-u4 scans app.js, lib.js, index.html for codex, openai, gpt, gemini, llama, mistral). The new words are "agents", "usage", "no usage in the run files". Test Runs may use neutral labels only.
6. Timers and listeners. Add no setTimeout, setInterval, addEventListener, storage write or innerHTML; closing the hint is one call inside the click path that already exists.
7. Escaping. Texts go through setText/textContent and fact()/esc(); k and n are String() integers. Extend an existing escaping test with an agent id `<img src=x onerror=1>` that has no usage and require no `<img` in the cost text or method.
8. Tests that can fail. A fake page has no layout and no stacking: its first-row test proves the same elements, no insert, remove or hidden toggle in the panel, not the 27.4 px; the geometry gate below is what proves it. Run each new test on base b356d64 (`git archive b356d64 | tar -x -C <tmpdir>`, copy the new test files in): red. On a throwaway copy, put `setShown` back on the status, drop the hint closing, drop the k < n branch, make the Run gate permissive: each must turn its test red.
