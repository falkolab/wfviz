# Node guide: steady UI (unit web-steady)

Read with docs/guides/common.md. The spec (items 1-8) is in the node task; this file says what binds, what you may break, where it is easy to go wrong, and how to check. Tests are named, not numbered by line.

## Rules that bind
- docs/contract.md, intro: "wfviz is universal"; no role, phase, label, node code, file name or result shape of our method "may be required or hard-coded" in src/, web/, bin/. test/integration/universal.test.mjs scans every code line of web/; only lines that start with // are skipped, so a trailing comment counts.
- contract §2: "Every value the UI shows is a Fact"; unknown carries a `reason`. "Label pattern (inferred, never required)". "Fallback matrix": rows by `phase` "in order of first appearance", agents with no phase in one row "phase unknown", cells in start order "captioned with the label as is (else the agentId)", "the cells carry the label's own prov", a mixed run shows "a note that says how many labels did not parse".
- contract §4: `run` snapshots come "at most once per second per run"; `event` has `seq` "per run, from 1, no gaps"; "The UI animates and logs from `event`, not from snapshot differences."
- AGENTS.md, Hard rules: "Never invent data"; "Roles, phases and labels come from run data, never hard-coded"; "The visualizer only observes"; "Write only the files your node owns"; no git commit, stash or reset; ES modules, Node >= 20, zero npm dependencies.
- AGENTS.md, "Images and video": do not read screenshots in the orchestrating session; check the page through DOM text, a subagent reads any picture.
- graph.md §9: "A node's gate can block on a test outside its owned paths that asserts the old contract"; a directory given to `node --test` on Node 22+ needs an index.js shim (test/server/index.js loads every *.test.mjs, so a new test file needs no list). Only high and medium findings send work back.

## Files you own and tests the spec invalidates
- Own: web/app.js, web/lib.js, web/index.html, web/style.css, test/server/web-lib.test.mjs, test/server/web-u3.test.mjs (new; import `test` from ./helpers.mjs). test/server/web-u2.test.mjs does not exist: the U2 tests are at the end of web-lib.test.mjs. Add no other file under web/.
- Not yours, list in your note: recognised items have no id; contract §3 names `agentId` and `from` but not `path` (src/model/recognize.mjs sets it; `from` is shared by all items of one result).
- Assertions to rewrite with the same intent (all in web-lib.test.mjs, say so in the note): "no timer re-renders on an interval" (no `setInterval`, exactly 2 `setTimeout(`); "a snapshot times the log lines again" (no `setInterval`); "the log is a pane fixed at the bottom" (`position: fixed`, `max-height: 35vh`, `body.style.paddingBottom`, `ResizeObserver(syncLogPadding)`); "every data string reaches the page through esc()" (literal needles such as `esc(o.title)`, `esc(l.message)`); "run option" (asserts `(name unknown) · ? · wf_1`).
- Assertions that stay and constrain you: "app.js parses, and every name it imports" needs one `import {...} from './lib.js'` of over 20 names, all functions (no exported constant); "every element app.js looks up by id" needs each `$('#id')` in index.html or as a literal id="..." in app.js (the three handles); the "matrix cell" tests fix `cell.tags` (strings, start order), `shown`, `count`, so for item 5 add a field with tag and state instead of reshaping `tags`; keep `elapsedFact(run, now)`, `parsedAgents`, `matrixRoles`, `matrixUnits`.

## Traps
- Keys. Findings and verdicts: agentId + `path`. Tests: several summaries of one string share agentId and `path` (recognize.mjs scanString), so add the ordinal inside (agentId, path); "k of n" counts all rows of that agent in `recognized.tests`, not the 8 shown (`slice(-8)`).
- Keys. Join parts with JSON.stringify([...]), never `a|b`. The "phase unknown" row, a phase titled like it, and the log's missing-events marker (`lineSeq` gives its `from`) need separate key spaces: a marker from=5 must not collide with line seq 5.
- Inventing. A fallback caption is the label through its own Fact (prov kept), else agentId with the label's unknown reason as tooltip; never split it into role/unit. Role and unit in a tests row only when the Run has both. A missing count in a tests row prints a bare "?" today: give the reason (the report card uses `unk('not in the summary')`).
- Undecided by the spec, decide, test and name in the note: how agents with no label at all (before 2.1.271) count in "N labels do not parse as role:unit" (recommended: every agent outside the matrix); where the "phase unknown" row sits (recommended: by first appearance); wording for N = 1.
- Coupling. No `AGENTS.md`, `graph.md`, `docs/guides`, `codex`, literals like 'implement', 'judge', 'fix', node codes like 'U2' on any line, comment tail included. Roles, units, phases come from data; test Runs may use our labels, the code may not.
- Full re-render left. Today these assign innerHTML on each snapshot: renderStatus, renderSteps, renderRoles, renderFacts, renderLegend, renderRight, renderTests, renderLogMeta, renderView, drawTimelineEdges (svg), renderLogAll (first backlog and the reorder branch of retimeLog), the hover panel (syncHover(true)). renderReport, renderRunSelect and renderDrawer already skip identical content: keep that. Afterwards `grep innerHTML web/app.js` shows no write into a container that has children, except a deliberate reset.
- Flicker is mostly restarted CSS animations (`slidein` on .acard and .fcard, `draw` on edges) and lost transitions: an unchanged node must not replay them, and update in place rather than replace. paintAllFlashes() after render() and refreshSelection() write class and style on unchanged nodes: touch only nodes whose highlight state changed.
- `equal(prev, next)` compares displayed values (a tuple or html string), never object identity: each snapshot is newly parsed JSON. Running bars use Date.now(), so their geometry changes legitimately; nothing else may change when the run did not.
- Order is data: matrix cells are siblings of one CSS grid (position = DOM order), findings are newest first and cut at 60, lanes and log lines are ordered. planPatch must also give the final order or moves. Test insert in the middle, reorder, remove, duplicate key (throw or deterministic), empty prev, inputs not mutated.
- Keep a Map key -> element, not a selector built from a data string. Every other writer of a container (renderEmpty, the switch between matrix, fallback and mixed, selectRun, a tab drawn for the first time) clears that Map, or you diff against DOM that is gone.
- Scroll: write scrollTop only in the log follow-bottom rule (isNearBottom) and on first fill; column, view and drawer scroll must survive a snapshot.
- Timers. Exactly one 1 s interval, started by one function that clears the old handle (selectRun runs again at every SSE reconnect); stopped when the run is final (isFinalStatus), not running (elapsedFact stops counting) or another run is selected. A tick calls elapsedFact(state.run, Date.now()) and sets only textContent of the elapsed span (no title, class, innerHTML). Put the decision in a pure function (e.g. clockTick(run, now) -> ms or null) and test it.
- Listeners. Drag: add move/up listeners at drag start, remove on pointerup, pointercancel and lost capture (or capture on the handle); the first press of a double click must not save a size; save on release, no debounce timer (a test counts timers).
- Storage. Every localStorage read, write and removeItem in try/catch; a stored value is untrusted (NaN, Infinity, negative, text): validate, clamp, and clamp again on window resize because 50% of the width moves. Two columns at 50% leave no centre: pick a centre minimum, test it, name it in the note.
- Layout. Set sizes as CSS variables (--left-w, --right-w, --log-h), not inline grid-template-columns, which beats the `@media (max-width: 1100px)` one-column rule; hide the handles there. Columns that scroll inside themselves need a viewport-height layout with the log in flow; header height varies (demo banner, wrapped .top, #steps), so let CSS size it. A collapsed log keeps its saved height.
- Escaping. Every data string through esc(), attributes and data-* keys included: note, captions, "k of n", role, unit. New element types must join HOVER_SELECTOR, flashTargets, refreshSelection and the click handler (`.cell[data-agent]`, `.tl-bar`, `.acard`); make fallback cells `.cell` with data-agent.
- Item 8: units are row labels (`.mrow-label .u`), roles are column headers (`.mhead`, `minmax(44px,1fr)`); "matrix header" is ambiguous. Wrap, never ellipsize or clip, below 24 characters in both; name your reading in the note.

## How to check each item by hand
Start `node bin/wfviz.mjs --no-open --port 0 --idle 0 --root fixtures/claude-projects --since Infinity`; never `--demo` in place of real data. Read the page by DOM text and console JS. A running run needs a live workflow, which the orchestrator starts.
1. Console: `n=0; new MutationObserver(r=>n+=r.length).observe(document.body,{subtree:true,childList:true,attributes:true,characterData:true})`, keep `k=document.querySelector('.cell')`, wait 3 s on an unchanged run: n is 0 (a flash excepted) and `k` is still in the document. planPatch tests cover the rest.
2. Drag each handle: `getComputedStyle(document.documentElement).getPropertyValue('--left-w')` changes at once and survives reload; double click restores the default and removes the key; drag past 160 px, 50%, 80 px, 60%; make localStorage throw before load and see defaults; a long findings list scrolls in its column and the log top stays; at 1000 px width the layout is stacked.
3. Fixture wf_6509ce25-20a (judge and fixer labels do not parse) and `--root fixtures/synthetic/legacy-2.1.206` (label "synthesis") are mixed runs: matrix plus fallback rows and the note. All-unparsed: unit test on a hand-built Run.
4. On a live run the elapsed text changes each second and the observer of item 1 sees only that text node; on a final run, or after selecting another run, it stays still for 3 s.
5. A unit with rounds shows `#r1#r2#r3` in start order; a cell with two agents lists each tag and state (hand-built Run if no fixture has one).
6. No fixture has test rows: a hand-built Run with two summaries in one result gives "label · summary 1 of 2" and "2 of 2", with role and unit when parsed.
7. An unnamed run's option shows the id once and "(no name)".
8. A 40-character unit and role in a hand-built Run: full text in the DOM, `getComputedStyle(el).textOverflow` is not `ellipsis`, `el.scrollWidth <= el.clientWidth`.
Before finishing run `node --test test/` once: all pass, 0 skipped.
